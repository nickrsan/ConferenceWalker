## 1. Input Prompt & Understanding

### User Prompt:
> "It looks like maybe in the data processing code, the reported OpenStreetMap IDs aren't correct - these should be the IDs that OpenStreetMap has for the node, not any internal numbering.
>
> Additionally, I'd like a toggle in the user interface to exclude data only sourced from overture. It is quite noisy (with poor positional accuracy), so it may help to be able to see the map without those. Please confirm that in the pre-processing pipeline, the OpenStreetMap information takes precedence when merging information between the two sources.
>
> I'd also like the toggle to show the OSM and GERS IDs and to be able to disable Overture data to be behind a new settings panel. Thank you!"

### Problem Interpretation & Goals:
1. **Canonical OpenStreetMap IDs in Data Processing**:
   - In `pipeline/preprocess.py`, `osmium export` was previously executed without `-a type,id`. As a result, the exported GeoJSON did not include the `@id` and `@type` attributes from OSM entities, causing the pipeline to fall back to synthetic sequential identifiers (`node_{idx}`).
   - The fix requires adding `-a type,id` to the `osmium export` command, parsing genuine OpenStreetMap node/way IDs from `@id` / `id`, normalizing any type prefixes (`node/12345` -> `12345`), and writing the genuine OSM ID into `osm_id` and `id` (`osm_{osm_id}`).
   - Verify that OpenStreetMap node IDs in the dataset correspond to real OpenStreetMap entity numbers (e.g., `90498377` for Cathedral Square).

2. **Confirmation & Enforcement of OpenStreetMap Precedence**:
   - Confirm and guarantee that when merging records between OpenStreetMap and Overture Maps in `pipeline/dedupe.py`, OpenStreetMap information strictly takes precedence.
   - Specifically:
     - **Coordinates**: Retain OpenStreetMap coordinates directly to prevent positional degradation from noisy Overture coordinates (avoiding averaging coordinates between the two sources).
     - **Name**: Retain the OpenStreetMap name (unless missing or a generic category fallback).
     - **Category**: Retain the OpenStreetMap category classification.
     - **Address, Phone, Website, Opening Hours**: OpenStreetMap data takes precedence, with Overture providing enrichment for missing attributes.
     - **Sources & IDs**: Keep `sources: ["osm", "overture"]`, retaining both `osm_id` (from OSM) and `overture_id` (from Overture GERS).

3. **Toggle to Exclude Overture-Only Data**:
   - Provide a toggle in the application to exclude POIs only sourced from Overture Maps (`sources: ['overture']`) to reduce positional inaccuracy and map clutter.
   - Retain all OpenStreetMap places (`sources: ['osm']`) and merged places (`sources: ['osm', 'overture']`).
   - Implement state handling in `FilterStore` with reactive subscription updates, MapLibre GL layer filter expression generation, `localStorage` persistence, and URL query parameter support (`?exclude_overture=true`).

4. **Dedicated Settings Panel in the User Interface**:
   - Create a new settings panel accessible via a `⚙️ Settings` button in the sidebar header.
   - Relocate the "Show OSM & GERS IDs" debug toggle from the filter quick-toggles into the new settings panel.
   - Place the "Disable Overture-only data" toggle into the settings panel under a "Data Sources" section with clear descriptive text.
   - Coordinate panel transitions: opening Settings collapses Filters, opening Filters collapses Settings, and closing Settings restores the distance-sorted venue list.

## 2. Actions Taken & Code Generated

### 1. Data Processing Pipeline (`pipeline/`):
- **`pipeline/preprocess.py`**:
  - Added `-a type,id` to the `osmium export` command in `extract_osm_pois`.
  - Updated ID extraction to parse canonical numeric node and way IDs from `@id` / `id`, stripping any type prefixes (e.g. `node/90498377` -> `90498377`), and populating `osm_id` and `id` (`osm_{osm_id}`).
  - Re-executed the preprocessing pipeline against Sacramento core data, generating an updated `public/data/sacramento_pois.geojson` containing 2,856 deduplicated POIs with genuine OSM IDs (1,657 OSM-only, 1,007 Overture-only, and 192 merged).
- **`pipeline/dedupe.py`**:
  - Updated `merge_two_pois(poi_a, poi_b)` to guarantee that OpenStreetMap data strictly takes precedence regardless of argument order.
  - Retained exact OpenStreetMap coordinates rather than averaging them with Overture coordinates, eliminating positional drift and noise.
  - Ensured OpenStreetMap venue name, category, address, phone, website, and opening hours take precedence, while preserving Overture enrichment for unpopulated fields and capturing `overture_id`.
